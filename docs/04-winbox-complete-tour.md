# 04 — WinBox Complete Guided Tour

> [!IMPORTANT]
> This chapter teaches the WinBox shell and the most important windows. The
> exhaustive menu/submenu reference now lives in the
> [WinBox Menu-by-Menu Field Manual](winbox/README.md). Use that manual when you
> need to know what every visible menu contains, what opens when it is selected,
> how an item is created, and how the GUI maps to RouterOS CLI.

WinBox is a graphical client for RouterOS, not a separate configuration language. Most windows mirror a CLI menu. A menu can appear or disappear depending on RouterOS version, packages, device hardware, license, and user permissions.

## 1. The loader: before you connect

The connection window contains:

| Control | Meaning | Good practice |
|---|---|---|
| Connect To | router IP, IPv6 in brackets, or MAC | prefer IP after initial setup |
| Login / Password | RouterOS credentials | use named user; do not share admin credentials |
| Keep Password | store credential in managed entry | avoid on shared/untrusted workstation |
| Neighbors | MNDP/CDP/LLDP-visible devices | discovery is local-scope, not authoritative inventory |
| Managed | saved routers/groups | label site, role, and management address clearly |
| Connect To RoMON | reach target through a RoMON agent | secure and restrict RoMON first |
| Open in New Window | keep loader available | useful for multi-router labs |

Click the IP column to connect by IP; click the MAC column to use MAC-WinBox. If both fail, verify PC addressing, local firewall, VLAN, cabling, RouterOS service state, and allowed-source/interface policy.

## 2. Main frame and safety controls

After login, identify these before changing anything:

- session title: router identity, user, and target address;
- **Safe Mode** button: automatic rollback if the session dies abnormally;
- Undo/Redo: backed by `/system history`;
- CPU and memory indicators: a slow GUI may reflect router load, not only network latency;
- window/workspace controls: layouts can be retained per router/session;
- search/filter fields: use them instead of visually scanning hundreds of objects.

### Safe Mode drill

1. Connect by IP.
2. Click **Safe Mode**; confirm it becomes active.
3. Change the management IP to a wrong subnet.
4. Let the session fail without cleanly releasing Safe Mode.
5. Reconnect after RouterOS rolls the floating changes back.

CLI equivalent is `Ctrl+X` (or `F4` in supported contexts). `Ctrl+D` exits a CLI Safe Mode session without committing. Do this drill only in a lab.

## 3. List-window controls

RouterOS configuration consists mostly of lists of objects. Learn the common controls once:

| Control | Action |
|---|---|
| `+` | add an object |
| `-` | remove selected static object |
| check mark | enable |
| `X` | disable without deleting |
| note/comment | attach intent |
| copy | clone an object as a starting point |
| funnel/filter | restrict visible rows |
| right-click columns | show additional properties |
| double-click row | open detailed properties/status |
| drag row | reorder ordered rules such as firewall filters |

Flags matter. Common flags include `X` disabled, `I` invalid, `D` dynamic, `R` running, `A` active, `H` hardware-offloaded, and protocol-specific flags. Read the legend in that exact window; the same letter can have context-specific meaning.

Dynamic objects are generated by services or protocols. You normally change the parent configuration rather than trying to delete a dynamic child.

## 5. The most important submenus

### Interfaces

Open an Ethernet interface and inspect:

- **General**: name, default name, MAC (where editable), MTU, ARP mode;
- **Ethernet**: auto-negotiation, advertised rates, flow control, PoE where supported;
- **Status**: link rate/duplex, SFP data, running state;
- **Traffic**: live bit/packet graphs;
- **Stats**: errors, drops, FCS/alignment counters.

Do not force speed/duplex on one end only. A link that is “running” can still have severe errors.

### Bridge

- **Bridge**: creates logical bridges and controls STP/VLAN filtering.
- **Ports**: assigns physical/logical interfaces, PVID, frame admission, path cost.
- **VLANs**: maps VLAN IDs to tagged/untagged ports, including the bridge CPU port.
- **Hosts**: learned MAC addresses and egress ports.
- **MSTI/Ports**: advanced spanning-tree contexts when used.

Never enable `vlan-filtering=yes` remotely until the bridge VLAN table includes the management VLAN and correct bridge CPU membership.

### IP

- **Addresses**: Layer 3 addresses bound to interfaces.
- **ARP**: IP-to-MAC neighbor state.
- **DHCP Client/Server/Relay**: address acquisition and delivery.
- **DNS**: upstream/cache/static records and remote-request behavior.
- **Routes**: IPv4 FIB-facing route view; advanced policy lives under Routing too.
- **Firewall**: Filter, NAT, Mangle, Raw, Service Ports, Connections, Address Lists, Layer7.
- **Services**: WinBox/SSH/Web/API listeners and source restrictions.
- **IPsec**: profiles, proposals, peers, identities, policies, installed SAs.
- **Pools**: reusable address ranges for DHCP/PPP.
- **Hotspot**: captive portal; note its IPv4/NAT dependency.

### Routing

RouterOS v7 concentrates protocol configuration and policy here:

- **Tables**: named routing tables, optionally installed in FIB;
- **Rules**: source/destination/interface-based table lookups;
- **Filters**: routing-policy chains;
- **OSPF**: instances, areas, interface templates, neighbors, LSAs/routes;
- **BGP**: templates, connections, sessions, advertisements/status;
- **BFD**: fast failure detection where supported and justified;
- other protocols appear by version/package.

### System

Check these on every device:

- Resources: CPU, memory, storage, architecture, uptime, version;
- Packages and upgrade status;
- RouterBOARD firmware on physical devices;
- Users, groups, SSH keys and certificates;
- Clock/NTP: wrong time ruins logs and certificates;
- Logging actions/topics;
- Scheduler and Scripts: understand every automated change;
- History: exact changes and undo/redo state;
- Health: temperature/voltage/fans where sensors exist.

## 6. Filters, columns and detail mode

Large tables are usable only when you expose the right evidence. In **IP → Routes**, add columns for destination, gateway, distance, immediate gateway, routing table, pref-src, and protocol attributes. In BGP views, expose AS path, local preference, MED, communities, and peer/session.

Use filters such as destination prefix or comment. A WinBox filter changes only the display; it is not a RouterOS forwarding filter.

## 7. Files and drag-and-drop

WinBox can upload/download files. Typical objects include `.rsc` exports, `.backup` backups, certificates, package files, PCAPs, and support outputs. Router storage may be small. Check **Files → Free Space** or `/system resource print` before uploading a package/capture.

Never download a sensitive backup to a shared Downloads folder and forget it.

## 8. GUI-to-CLI learning method

For each new GUI action:

1. make the change in Safe Mode;
2. open **System → History** or run `/system history print detail`;
3. find the recorded CLI action;
4. export the relevant menu;
5. undo and recreate it in CLI;
6. verify both produce the same object.

This turns WinBox from a collection of mysterious forms into a visual CLI reference.

## 9. Common WinBox mistakes

- Connecting to a MAC address and assuming routed management works.
- Editing the wrong router because multiple windows look identical—set clear identities.
- Filtering a table, forgetting the filter, and believing objects disappeared.
- Deleting a dynamic object instead of fixing its parent service.
- Dragging a firewall rule to the wrong order.
- Enabling bridge VLAN filtering before the CPU/management path is defined.
- Saving passwords on an uncontrolled workstation.
- Treating an empty menu as proof a feature does not exist; check package, permission, and hardware.
- Closing Safe Mode cleanly when you meant to trigger rollback.

## WinBox checkpoint

Without guessing, demonstrate:

1. IP and MAC connection to an isolated router;
2. Safe Mode rollback;
3. adding a route column and a display filter;
4. creating an address in WinBox, locating its history command, undoing it, and recreating it in terminal;
5. exporting/downloading a non-sensitive `.rsc` file;
6. locating interface errors, DHCP leases, firewall counters, routes, logs, CPU profile, and OSPF/BGP status windows.
